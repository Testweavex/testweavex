Getting Started

From install to your first gap report in under 10 minutes.

  1. Install and initialise

    pip install testweavex
tw init --llm-provider anthropic

    This creates testweavex.config.yaml in your project root and a testweavex/skills/ folder with the 10 built-in skill files.

  2. Run your test suite

    tw                         # same as pytest — all flags work
tw tests/login.feature    # run a specific feature
tw -k smoke -n 4          # filter + parallel

    Results are stored automatically in .testweavex/results.db. No configuration required.

  3. View your first gap report

    tw gaps --limit 20

    TestWeaveX compares your TCM against your automation suite and surfaces unautomated tests ranked by priority score.

  4. Open the Web UI

    tw serve

    Opens the dashboard at http://localhost:8080 — test cases, gap report, run history, and LLM settings in one place.

Team mode: Add --results-server https://your-server --token $TOKEN to any tw command to share results across your team. See the Server Deployment section for one-command container setup.

Configuration

Create testweavex.config.yaml in your project root. All values support ${ENV_VAR} interpolation.

# testweavex.config.yaml
llm:
  provider: anthropic        # openai | anthropic | ollama | azure
  model: claude-sonnet-4-6
  api_key: ${ANTHROPIC_API_KEY}
  temperature: 0.3
  max_retries: 3
  timeout_seconds: 30

results_server: ${TESTWEAVEX_SERVER}  # optional — team mode

tcm:
  provider: none              # testrail | xray | none

gap_analysis:
  scoring_weights:
    priority:  0.30
    test_type: 0.25
    defects:   0.20
    frequency: 0.15
    staleness: 0.10
  match_threshold: 0.65
  top_gaps_default: 10

Server Deployment

Run tw serve in a container so every team member can access the shared Test Case Management dashboard from their browser — no local installation required. A named volume persists the SQLite database across restarts; swap in DATABASE_URL pointing to PostgreSQL if you need multi-instance or cloud-hosted storage.

Quick start (any platform): clone the repo, then run docker compose up -d (or podman compose up -d). The UI is available at http://<server-ip>:8080 within seconds.

Option 1 — Docker Desktop (Mac / Windows)

  1. Install Docker Desktop

    Download and install from docker.com/products/docker-desktop. Start Docker Desktop and wait until the whale icon in the menu bar shows Docker Desktop is running.

  2. Clone the repository

    git clone https://github.com/testweavex/testweavex.git
cd testweavex

  3. Set your LLM API key (optional)

    Create a .env file in the project root. Docker Compose reads it automatically:

    ANTHROPIC_API_KEY=sk-ant-your-key-here
# OPENAI_API_KEY=sk-your-openai-key
    Never commit .env to git. It is listed in .gitignore by default.

  4. Build and start the container

    docker compose up -d

    Docker Desktop builds the image, starts the container, and mounts the data volume. Open Docker Desktop → Containers to see it running.

  5. Open the dashboard

    Navigate to http://localhost:8080 in your browser.

    To access from another machine on the same network, use the server's IP address: http://<server-ip>:8080

Option 2 — Podman Desktop (Mac / Windows / Linux)

Podman Desktop is a free, open-source GUI for Podman — rootless containers with no background daemon required.

  1. Install Podman Desktop

    Download from podman-desktop.io and follow the installer. On first launch, Podman Desktop guides you through initialising the Podman machine (a lightweight VM on Mac/Windows).

  2. Initialise the Podman machine (Mac / Windows only)

    podman machine init
podman machine start

    On Linux this step is not needed — Podman runs natively.

  3. Clone and set up

    git clone https://github.com/testweavex/testweavex.git
cd testweavex
# Create .env with your LLM API key (optional)
echo "ANTHROPIC_API_KEY=sk-ant-your-key" > .env

  4. Build and start with Podman Compose

    Install podman-compose if you haven't already:

    pip install podman-compose

    Then start TestWeaveX:

    podman-compose up -d

    Alternatively, use the Podman Desktop GUI: open Images → Build, point it at the Dockerfile, then run the image with port 8080:8080 and a volume for /data.

  5. Open the dashboard

    Navigate to http://localhost:8080.

    In Podman Desktop you can also click the port link directly in the Containers view.

Option 3 — Plain Docker / Podman CLI (Linux servers, CI)

For headless servers and CI pipelines where a GUI is not available.

# 1. Build the image
docker build -t testweavex:latest .

# 2. Create a named volume for persistent data
docker volume create testweavex-data

# 3. Run the server
docker run -d \
  --name testweavex \
  -p 8080:8080 \
  -v testweavex-data:/data \
  -e DATABASE_URL=sqlite:////data/.testweavex/results.db \
  -e ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY} \
  --restart unless-stopped \
  testweavex:latest

# 4. Verify it is healthy
docker ps
curl http://localhost:8080/api/dashboard
# 1. Build the image
podman build -t testweavex:latest .

# 2. Create a named volume for persistent data
podman volume create testweavex-data

# 3. Run the server (rootless — no sudo needed)
podman run -d \
  --name testweavex \
  -p 8080:8080 \
  -v testweavex-data:/data \
  -e DATABASE_URL=sqlite:////data/.testweavex/results.db \
  -e ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY} \
  testweavex:latest

# Enable auto-restart via systemd (rootless)
podman generate systemd --name testweavex --files --new
mkdir -p ~/.config/systemd/user
mv container-testweavex.service ~/.config/systemd/user/
systemctl --user enable --now container-testweavex.service

Accessing from Other Machines

The container binds to 0.0.0.0:8080 by default, so it accepts connections from any network interface. To reach it from another machine:

  1. Find the server's LAN IP: ip a (Linux) or ipconfig (Windows).
  2. Open http://<server-ip>:8080 in the browser on the remote machine.
  3. If a firewall is active, allow port 8080: ufw allow 8080/tcp (Ubuntu) or add a rule in Windows Defender Firewall.

Point your tw CLI on each developer machine at the server so run results are shared: 

# testweavex.config.yaml on each developer machine
results_server: http://192.168.1.50:8080

# Or pass it inline:
tw --results-server http://192.168.1.50:8080 --token $TESTWEAVEX_TOKEN

PostgreSQL Backend (Team Mode)

For larger teams or cloud deployments, replace the SQLite volume with a Postgres database:

# docker-compose.override.yml — add to your project root
services:
  testweavex:
    environment:
      - DATABASE_URL=postgresql://tw:secret@db:5432/testweavex
    depends_on: [db]

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: tw
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: testweavex
    volumes:
      - pg-data:/var/lib/postgresql/data

volumes:
  pg-data:
Tip: Run docker compose up -d — Compose merges docker-compose.yml and docker-compose.override.yml automatically. Install the postgres extra first: pip install "testweavex[postgres]" or add it to the Dockerfile.

Tutorial — Testing practice.expandtesting.com

This hands-on tutorial builds a complete TestWeaveX project against practice.expandtesting.com — a free QA practice site with 70+ pages covering login flows, React CRUD apps, forms, file handling, and more. By the end you will have automated tests, a gap report, and LLM-generated suggestions for uncovered scenarios.

from steps import auth_steps, notes_steps, form_steps  # noqa: F401

BASE_URL = "https://practice.expandtesting.com"

@pytest.fixture(scope="session")
def browser_instance():
    with sync_playwright() as p:
        b = p.chromium.launch(headless=True)
        yield b
        b.close()

@pytest.fixture
def page(browser_instance):
    ctx = browser_instance.new_context()
    pg = ctx.new_page()
    yield pg
    ctx.close()

Architecture

TestWeaveX is a pytest plugin with a thin CLI wrapper. All functionality flows through one of three pipelines.

PipelineInputOutput
GenerationFeature description + skill fileApproved Gherkin + step definitions in repo
ExecutionFeature files + pytest configTest results in storage + TCM updated
Gap AnalysisTCM test cases + automation suiteRanked gap list + optional generated automation

Component Map

ModuleResponsibilityPhase
core/models.pyPydantic data models — shared contract1
core/config.pyYAML config loader1
storage/sqlite.pyLocal SQLite persistence (default)1
llm/Provider-agnostic LLM adapter layer2
skills/YAML skill files for each test type2
generation/Feature → Gherkin → step definitions3
execution/plugin.pypytest plugin hooks4
gap/Gap detection, scoring, automation trigger5
web/FastAPI + React dashboard6
tcm/TestRail + Xray connectors7

Stable ID Algorithm

Every test case gets a deterministic 64-character ID derived from its feature file path and scenario name. The algorithm is frozen — never change it after first deployment.

import hashlib

def generate_stable_id(*parts: str) -> str:
    key = "|".join(parts).encode("utf-8")
    return hashlib.sha256(key).hexdigest()  # full 64 chars

Adding a Custom Skill

Create testweavex/skills/custom/your-skill.yaml:

name: custom/your-skill
display_name: Your Skill Name
description: What this skill generates

prompt_template: |
  You are a senior QA engineer.
  Feature: {feature_description}
  Generate {n_suggestions} test scenarios that...
  Return JSON: title, gherkin, confidence, rationale, suggested_tags

assertion_hints:
  - Verify primary outcome
tags: [custom]
priority: 3
